# Security Policy

## Supported Versions

Security fixes are applied to the current development line. Older releases may not receive security updates unless explicitly stated in their release notes.

## Reporting a Vulnerability

Please do not report exploitable vulnerabilities in public issues or pull requests.

Use GitHub's **Report a vulnerability** workflow on this repository when private vulnerability reporting is available. If that option is unavailable, contact the repository maintainers privately through a verified channel before sharing exploit details.

Include:
- affected commit, tag, or release;
- affected component and deployment context;
- reproducible steps and a minimal proof of concept;
- expected impact and any known mitigations.

Do not include real credentials, personal data, or third-party secrets in reports.

## Response Expectations

Reports are triaged for reproducibility, severity, affected versions, and remediation options. Acknowledgement and remediation timelines are not guaranteed. Coordinated disclosure is preferred; please allow maintainers reasonable time to investigate and release a fix before public disclosure.

## Scope

This policy covers code and workflows maintained in this repository. Third-party services, dependencies, and infrastructure are subject to their respective security policies.
